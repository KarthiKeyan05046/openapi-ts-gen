## What it does

Point it at a local JSON/YAML file or a live API URL and it produces two ready-to-use TypeScript files:

| Output file | Contents |
|---|---|
| `schema.ts` | Full type definitions for `paths`, `components`, `operations` — generated by `openapi-typescript` |
| `api.ts` | `ApiRoute` enum + `buildRoute()` helper + `*_Payload` type aliases for every endpoint that accepts a request body |

---

## Features

- Supports **OpenAPI 3.0 and 3.1** schemas
- Accepts **any OpenAPI specification format** — JSON or YAML, local file or remote URL
- Auto-detects format from file extension or HTTP `Content-Type` header, with JSON → YAML fallback
- Singularizes plural path segments automatically — `/post/genders/` → `Post_Gender_Payload`
- Generates a typed **`ApiRoute` enum** — no more hardcoded path strings
- Generates a **`buildRoute()`** helper to safely substitute path parameters at runtime
- Generates **`*_Payload` type aliases** wired directly to `paths[...]['requestBody']`
- **Zero runtime cost** for types — all erased at compile time
- **React Native / Metro compatible** — uses regular `enum`, not `const enum`
- Friendly interactive CLI — no flags to memorize

## Usage

```bash
npx openapi-ts-gen
```

The CLI will ask two questions:

```
openapi-ts-gen — OpenAPI → TypeScript generator

? OpenAPI schema source (local file path or URL): https://api.example.com/openapi.json
? Output directory: ./src/api
```

**Accepted schema sources:**

| Format | Example |
|---|---|
| Remote JSON URL | `https://api.example.com/openapi.json` |
| Remote YAML URL | `https://api.example.com/openapi.yaml` |
| Local JSON file | `./specs/api.json` |
| Local YAML file | `./specs/api.yaml` or `./specs/api.yml` |

That's it. Two files are written to your output directory.

## Output

### `schema.ts`
```ts
// Generated by openapi-ts-gen — do not edit manually
export type paths = {
  '/post/genders/': {
    post: {
      requestBody: {
        content: {
          'application/json': components['schemas']['GenderBase'];
        };
      };
      responses: { ... };
    };
  };
  // ... all other paths
};

export type components = { ... };
```

### `api.ts`
```ts
import type { paths } from './schema';

// ── API Route Enum ────────────────────────────────────────────────────────────
export enum ApiRoute {
  PostGenders                  = '/post/genders/',
  RolesRoleIdButtonsButtonId   = '/roles/{role_id}/buttons/{button_id}',
  RolesRoleIdPermissions       = '/roles/{role_id}/permissions',
  // ...
}

// ── Route Builder ─────────────────────────────────────────────────────────────
/**
 * Replace path parameters in a route template with actual values.
 * @example
 * buildRoute(ApiRoute.RolesRoleIdButtonsButtonId, { role_id: 42, button_id: 7 })
 * // → '/roles/42/buttons/7'
 */
export function buildRoute(
  route: ApiRoute,
  params: Record<string, string | number>,
): string { ... }

// ── Request Payload Types ─────────────────────────────────────────────────────
export type Post_Gender_Payload =
  paths['/post/genders/']['post']['requestBody']['content']['application/json'];
// ...
```

### Usage in your app

**Static routes (no path params):**
```ts
import type { Post_Gender_Payload } from './api/api';
import { ApiRoute } from './api/api';

const response = await fetch(ApiRoute.PostGenders, {
  method: 'POST',
  body: JSON.stringify(payload satisfies Post_Gender_Payload),
});
```

**Dynamic routes (with path params):**
```ts
import { ApiRoute, buildRoute } from './api/api';

// Substitutes {role_id} and {button_id} at runtime
const url = buildRoute(ApiRoute.RolesRoleIdButtonsButtonId, {
  role_id: 42,
  button_id: 7,
});
// → '/roles/42/buttons/7'

const response = await fetch(url, { method: 'GET' });
```

## Naming rules

### Enum keys

| Path | Enum key |
|---|---|
| `/post/genders/` | `PostGenders` |
| `/roles/{role_id}/permissions` | `RolesRoleIdPermissions` |
| `/roles/{role_id}/buttons/{button_id}` | `RolesRoleIdButtonsButtonId` |
| `/get/work-plans/list/` | `GetWorkPlansList` |

Path parameters (`{role_id}`) have their braces stripped and are PascalCased like any other segment.

### Payload type names

| Path | Payload type |
|---|---|
| `/post/genders/` | `Post_Gender_Payload` |
| `/put/edit/family/` | `Put_Edit_Family_Payload` |
| `/roles/{role_id}/permissions` | `Roles_RoleId_Permission_Payload` |
| `/get/work-plans/list/` | `Get_Work_Plan_List_Payload` |

Rules applied in order:
1. Split path by `/`, drop empty segments
2. Strip `{` `}` from path parameter segments (`{role_id}` → `role_id`)
3. Singularize plural words (`genders` → `gender`, `work-plans` → `work-plan`)
4. PascalCase each segment, join with `_`, append `_Payload`
