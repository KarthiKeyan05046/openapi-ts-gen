## What it does

Point it at a local JSON/YAML file or a live API URL and it produces two ready-to-use TypeScript files:

| Output file | Contents |
|---|---|
| `schema.ts` | Full type definitions for `paths`, `components`, `operations` — generated by `openapi-typescript` |
| `api.ts` | `ApiRoute` enum (every path as a typed constant) + `*_Payload` type aliases for every endpoint that accepts a request body |

---

## Features

- Supports **OpenAPI 3.0 and 3.1** schemas
- Accepts a **local file path** (JSON or YAML) or a **remote URL**
- Singularizes plural path segments automatically — `/post/genders/` → `Post_Gender_Payload`
- Generates a typed **`ApiRoute` enum** — no more hardcoded path strings
- Generates **`*_Payload` type aliases** wired directly to `paths[...]['requestBody']`
- **Zero runtime cost** for types — all erased at compile time
- **React Native / Metro compatible** — uses regular `enum`, not `const enum`
- Friendly interactive CLI — no flags to memorize

## Usage

```bash
npx openapi-ts-gen
```

The CLI will ask two questions:

```
openapi-ts-gen — OpenAPI → TypeScript generator

? OpenAPI schema source (local file path or URL): https://api.example.com/openapi.json
? Output directory: ./src/api
```

That's it. Two files are written to your output directory.

## Output

### `schema.ts`
```ts
// Generated by openapi-ts-gen — do not edit manually
export type paths = {
  '/post/genders/': {
    post: {
      requestBody: {
        content: {
          'application/json': components['schemas']['GenderBase'];
        };
      };
      responses: { ... };
    };
  };
  // ... all other paths
};

export type components = { ... };
```

### `api.ts`
```ts
import type { paths } from './schema';

// ── API Route Enum ────────────────────────────────────────────────────────────
export enum ApiRoute {
  PostGenders = '/post/genders/',
  GetGenders  = '/get/genders/',
  PutEditFamily = '/put/edit/family/',
  // ...
}

// ── Request Payload Types ─────────────────────────────────────────────────────
export type Post_Gender_Payload =
  paths['/post/genders/']['post']['requestBody']['content']['application/json'];

export type PutEditFamily_Payload =
  paths['/put/edit/family/']['put']['requestBody']['content']['application/json'];
// ...
```

### Usage in your app
```ts
import type { Post_Gender_Payload } from './api/api';
import { ApiRoute } from './api/api';

const response = await fetch(ApiRoute.PostGenders, {
  method: 'POST',
  body: JSON.stringify(payload satisfies Post_Gender_Payload),
});
```

## Path → Payload naming rules

| Path | Payload type name |
|---|---|
| `/post/genders/` | `Post_Gender_Payload` |
| `/put/edit/family/` | `Put_Edit_Family_Payload` |
| `/get/work-plans/list/` | `Get_Work_Plan_List_Payload` |
| `/post/event/group/meeting/` | `Post_Event_Group_Meeting_Payload` |

Rules applied in order:
1. Split path by `/`, drop empty segments
2. Singularize plural words (`genders` → `gender`, `work-plans` → `work-plan`)
3. PascalCase each segment (`work-plan` → `WorkPlan`)
4. Join with `_` and append `_Payload`
